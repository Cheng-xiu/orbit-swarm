# Frontend

Orbit Swarm 的前端是一个不需要构建工具的本地 Web 控制台。它由原生 HTML、CSS 和 JavaScript 组成，直接由后端静态托管。没有 React/Vue 运行时，也没有前端依赖安装步骤；修改文件后刷新浏览器即可看到结果。

根目录的 [`README.md`](../README.md) 适合第一次使用项目的人；这份文档专门说明前端的页面结构、交互约定、后端接口依赖和调试方法。

## 用户能看到什么

页面围绕一个工作流设计：用户只需要在底部唯一输入框描述目标，后台自动完成拆解、岗位分配、模型路由、执行和汇总。界面仍会显示足够的来源信息，让用户知道结果来自哪个岗位和 Agent，但不会把基础派发、心跳或普通执行回执刷进主聊天。

主要区域如下：

| 区域 | 作用 |
| --- | --- |
| 左侧任务栏 | 创建新任务、切换历史任务、查看任务状态 |
| 顶部运行条 | 显示当前任务标题、状态、Agent 数量和事件数量 |
| 中央消息区 | 显示用户消息、岗位成果、主管决定和关键系统通知 |
| 底部输入框 | 唯一用户入口；支持多行文本、附件元数据和 `Ctrl+Enter` 发送 |
| 右侧状态面板 | 显示模式、岗位在线数、日志搜索和状态流 |
| Provider/路由设置 | 新增 API、编辑档位岗位、选择 Provider/模型/执行器 |

## 文件说明

### `index.html`

页面骨架和可访问性标记。这里定义任务列表、消息区、输入框、状态面板和设置弹层的稳定 ID。JavaScript 通过这些 ID 绑定事件，因此修改 ID 时必须同步更新 `app.js`。

页面只引用两个资源：`styles.css` 和带查询版本号的 `app.js`。查询版本号用于避免浏览器继续使用旧脚本缓存；更新前端行为后如遇到旧页面，先强制刷新。

### `app.js`

前端状态和交互控制器，主要职责包括：

- 通过 `fetch` 读取 `/api/system`、`/api/tasks`、`/api/providers`、`/api/routes` 和 `/api/agent-profiles`。
- 通过 WebSocket（FastAPI 服务）或定时刷新（标准库服务）合并任务快照。
- 渲染任务列表、岗位卡片、来源标签、状态流、告警和最终结果。
- 把基础岗位派发、心跳和一般执行中事件过滤出主聊天，同时保留关键状态和完整后端日志。
- 维护 Provider 表单、岗位清单、Provider/模型/执行器路由和自然语言配置确认。
- 保存界面语言到浏览器 `localStorage`；运行配置仍由后端持久化。

`state` 是页面唯一的运行时状态对象。渲染函数应当从 `state` 读取数据，不要在 DOM 中维护第二份业务状态。后端返回新任务快照后使用 `mergeTask()` 合并，再调用对应的局部渲染函数。

### `styles.css`

负责布局、颜色、消息来源样式、状态标签、设置弹层和响应式规则。桌面端采用三栏布局；宽度降到 860px 时右侧检查器折叠；宽度降到 560px 时变为单列移动布局。设置弹层在 720px 以下改为单列，并允许面板内部滚动。

## 第一次使用

1. 先启动根目录 README 中介绍的标准库服务。
2. 浏览器打开 `http://127.0.0.1:8000`，等待右上角连接状态变为在线。
3. 在底部输入框写一个完整目标，例如“分析当前项目的错误处理并给出重构建议”。
4. 按 `Ctrl+Enter` 或点击发送。系统会先展示必要的澄清、工作流确认和资源估算。
5. 查看中央消息区的来源标签和右侧岗位状态；任务完成后阅读最终汇总。
6. 点击右上角设置按钮可以编辑 Provider、岗位数量、模型和执行器。保存后只影响新任务，已在运行的任务使用自己的配置快照。

输入框也能识别岗位配置命令，例如：

```text
模式2只保留系统架构师、后端开发组和测试开发组
模式1添加观察员2个，使用 OpenClaw
模式3文档执行组改为5个，模型 DeepSeek V4 Flash，接口 deepseek
```

配置命令会生成一条完成状态的确认任务，不会误启动普通集群流水。

## 设置面板使用说明

### Provider 目录

点击“新增”后填写：

- 标识：内部稳定 ID，例如 `my-provider`。
- 显示名称：界面中展示的名称。
- 接口地址：OpenAI 兼容接口的根地址，或 Anthropic API 根地址。
- 协议：`OpenAI Chat Completions` 或 `Anthropic Messages`。
- 模型列表：用逗号分隔，供岗位模型下拉框使用。
- 密钥：只写入当前服务进程内存；留空表示保存时保留现有密钥。
- 密钥环境变量：推荐填写环境变量名，例如 `MY_PROVIDER_API_KEY`，避免把密钥放进请求体。

Provider 保存后，前端只显示是否已配置和末尾提示，不会读取或渲染原始密钥。

### 岗位和模型路由

选择模式后，左侧岗位清单可以从后端岗位目录添加岗位、设置数量或移除岗位；每一行还可以选择执行器：

| 执行器 | 适合的任务 | 前置条件 |
| --- | --- | --- |
| 直接模型 | 通用分析、管理、测试、数据和安全 | Provider 支持所选 HTTP 协议 |
| Codex | 编码、仓库修改和代码审查 | 本机可执行 `codex` CLI |
| OpenClaw | 浏览器、本地自动化、文档和运维 | 本机可执行 `openclaw` CLI |
| Claude Code | Anthropic 原生代码工作流 | 本机可执行 `claude` CLI 和 Anthropic 路由 |

右侧路由行用于选择 Provider 和模型。保存岗位与路由后，后端会重建当前集群；在途任务不会被改写。路由下拉框只列出对应 Provider 已声明的模型，避免把不存在的模型 ID 提交给服务。

## 前端依赖的后端契约

前端只依赖 JSON REST 和可选 WebSocket，不直接访问模型 Provider。

| 请求 | 用途 |
| --- | --- |
| `GET /api/system` | 初始化模式、Agent、Provider、路由、执行器和持久化状态 |
| `GET /api/tasks` | 载入历史任务 |
| `POST /api/tasks` | 创建普通任务或提交中文岗位配置命令 |
| `GET /api/tasks/{id}` | 选择任务后刷新完整快照 |
| `GET /api/tasks/{id}/messages` | 打开任务详情和内部会话 |
| `POST /api/tasks/{id}/messages` | 在任务中继续讨论 |
| `POST /api/tasks/{id}/control` | 暂停、继续、取消和重试 |
| `GET /api/providers` | 加载 Provider 目录 |
| `POST/PUT/DELETE /api/providers...` | 新增、更新和停用 Provider |
| `GET/POST/PUT/DELETE /api/routes...` | 读取和保存岗位路由 |
| `GET/POST/PUT /api/agent-profiles` | 读取和保存各模式岗位清单 |
| `GET /api/logs?keyword=...` | 日志搜索 |

新增字段时优先保持向后兼容：旧字段继续返回，新字段在前端使用可选链和默认值读取。后端错误统一以 `{ "detail": "..." }` 返回，前端由 `api()` 转换成可读提示。

## 本地调试

前端没有独立开发服务器。推荐从项目根目录运行：

```powershell
python backend/server_stdlib.py --port 8000
```

浏览器打开页面后，可以在开发者工具 Console 中执行：

```javascript
state.system
state.tasks
state.active
```

常用检查命令：

```powershell
node --check frontend/app.js
Invoke-WebRequest http://127.0.0.1:8000/api/system
```

如果需要测试 WebSocket，安装后端可选依赖并改用 FastAPI 启动方式；标准库服务会自动使用轮询回退，不应因此报错。

## 修改前端时的约定

1. 新增用户可见消息时，先判断它是否属于关键状态、来源岗位成果、异常、裁决或最终汇总；普通派发和心跳应继续留在内部记录。
2. 新增按钮必须有可理解的文字或 `aria-label`，新表单控件要有稳定 ID 和移动端布局规则。
3. 修改后端字段时，为空、缺失和旧任务快照提供默认值；历史任务必须仍能被选择和渲染。
4. 长文本使用现有安全文本渲染函数，不要把用户输入直接拼接进 `innerHTML`。
5. 桌面至少检查 `1440×960`，移动至少检查 `390×844`；设置面板需要分别检查顶部和滚动到底部的布局。
6. 不要在前端保存 API key；只展示后端返回的脱敏状态。

## 常见问题

**页面打开但一直显示“连接中”**：确认服务端口正确，并访问 `/api/system`。如果接口能返回 JSON，通常是浏览器缓存了旧的 `app.js`，执行强制刷新。

**设置面板保存后岗位没有立刻变化**：保存操作只影响新任务，但服务会重建当前集群。刷新 `/api/system` 后应能看到新的岗位在线数；旧任务仍显示自己的配置快照。

**移动端看不到路由保存按钮**：设置面板自身可以滚动，向下滚动到“职位模型路由”底部即可；页面不会产生横向滚动条。

**为什么主聊天没有显示每个子 Agent 的全部过程**：这是刻意的消息降噪策略。完整 `agent_conversations` 仍由 `/api/tasks/{id}/messages` 和后端日志提供，主聊天只保留用户需要决策的内容。
